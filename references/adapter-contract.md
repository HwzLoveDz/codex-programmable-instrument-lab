# 新增程控仪器适配器约定

为新仪器新增支持时，只复制通用安全与留痕框架，不复制其他型号的命令。

## 必须确认

1. 制造商、准确型号、选件、固件和校准状态。
2. 官方编程手册、用户手册及命令适用的最低固件。
3. 传输层：USBTMC、VXI-11、HiSLIP、原生 TCP、串口或厂商 API；包括端口、终止符、二进制块、超时和最大消息长度。
4. 身份查询、错误队列、操作完成同步、状态保存/恢复方式。
5. 哪些命令只是读取，哪些会改变量程/触发，哪些会输出能量、切换继电器、擦除数据、校准、升级或复位。

## 适配器接口

适配器至少分离以下方法：

- `connect()` / `close()`：有界超时，失败后释放资源；
- `identify()`：返回未解析原文和结构化制造商/型号/序列号/固件；
- `query()`：只读；不能把多命令字符串偷偷带入写操作；
- `write()`：必须由已确认的测试计划调用并记录原命令；
- `read_binary_block()`：按协议长度读取，不能依赖换行；
- `errors()` / `wait_complete()`：读取错误队列和同步操作；
- `safe_state()`：仅在该型号的安全状态有官方定义且用户授权时调用。

对能输出能量的仪器，`connect()` 后不要自动恢复上次输出，也不要自动 `OUTPUT ON`。软件崩溃、通信中断和超时时，设计应倾向于输出关闭或硬件限值仍然生效。

## 会话生命周期

- 以完整实验为会话边界，而非单条命令或单次 CLI 调用。每台仪器建立一个受管连接，在身份确认后跨基线、配置、操作员步骤、各阶段采集与回读复用，实验收尾才执行必要的本地恢复并关闭连接。若仪器只允许一个远程客户端，不并发抢占它。
- 会话管理器要有明确的超时、关闭和异常清理路径；遵守仪器的空闲超时及保活能力，不能以无限等待代替连接管理。日志记录连接建立／关闭时间、阶段、最后一条命令、响应是否完整与恢复是否得到确认。
- 只读查询不默认触发状态恢复写入。发生超时、断链或半包时，将未获确认的写入和采样结果标记为不确定，停止后续依赖操作；不得自动重放输出开关、设置写入或 `READ?`。若需继续，重新识别仪器并核对实际设置和物理工况，再从新的阶段采集。
- 一次性 CLI 可以用于独立诊断；若它每次退出都断联，不得把一串这样的调用宣传为持久会话。跨人工步骤的闭环需要显式的 session 模式或同等受管机制。

## 最小回归测试

- 用本地假服务器测试终止符、拆包、超时、二进制块和连接关闭。
- 接真实仪器时先做 IDN、错误队列和截图/小数据块测试。
- 写命令只在无 DUT 或已知安全的校准环路中验证；每次只改变一项，并查询回读。
- 保存一份真实但已脱敏的命令日志作为兼容性证据，不把模拟服务器结果标成实机结果。
- 对没有独立命令 ACK 的非 SCPI 协议（例如 MDP-M01 USB 链路），以仪器状态帧确认状态，不把串口写入成功当作设备接受；参考 [MDP-M01/P906/L1060 联调边界](mdp-m01-p906-l1060.md)。
